# Contributing

## Document changes

- Edit the Markdown source before changing rendered/PDF copies.
- Preserve the numbered partner-document naming convention.
- Keep each topic anchored to one authoritative partner-facing file.
- Mark unvalidated claims, assumptions, and pending evidence explicitly.
- Do not move internal or NDA-preferred material into public-facing documents without an intentional review.
- Update `docs/partners/markdown/14_Data_Room_Index.md` whenever status, share level, or source-of-truth relationships change.

## Review checklist

Before merging a material documentation change, check:

- consistency with the Nain-first / Labrador-coast project framing;
- heat-first architecture and reuse → store → reject logic;
- black-box tenancy boundaries;
- community/FPIC and benefit commitments;
- technical, commercial, environmental, and schedule claims for validation status;
- cross-document terminology and units;
- accidental inclusion of personal, tenant-confidential, or otherwise restricted information.
